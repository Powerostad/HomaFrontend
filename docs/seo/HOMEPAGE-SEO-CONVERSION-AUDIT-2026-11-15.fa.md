# ممیزی صفحه اول هما و اصلاحات پیشنهادی — ۱۵ نوامبر ۲۰۲۶

## دامنه بررسی و سطح اطمینان

- آدرس مورد نظر: `https://myhoma.ir/`.
- تلاش برای دریافت HTML، robots و sitemap زنده انجام شد؛ وب‌خوان خطوط قابل‌خواندن از صفحه اصلی برنگرداند و درخواست مستقیم container به دامنه به خطای DNS خورد. **این به معنی خرابی سایت برای کاربران نیست**، اما تأیید مستقیم Production، مقایسه User-Agent، Search Console یا Core Web Vitals ممکن نشد.
- شواهد قطعی این بررسی از `Powerostad/HomaFrontend` شاخه `dev` و فایل‌های `Dockerfile`، `nginx.conf`، `render-bot.mjs`، `index.html`، صفحه `ProductLanding` و لایه `src/seo` است. این سورس الزاماً برابر با HTML فعال Production نیست.
- **پیش‌فرض ممنوع:** تصور اینکه مسیر SSR در `server.mjs` اکنون مستقر شده. Dockerfile فعلی build استاتیک Vite + Nginx + render-bot را راه‌اندازی می‌کند.

## پیام و معماری محتوای جدید

**جایگاه:** «هما؛ نسخه بهتر خونه‌ت.» با توضیح قابل‌درک «طراحی دکوراسیون خانه با هوش مصنوعی» از روی عکس فضای واقعی کاربر.

**مسئله‌ای که می‌فروشیم:** پیش از خرید، مشخص شود کدام وسایل مناسب‌اند، چه چیزی باید جابه‌جا شود و چه تغییری می‌تواند بهتر عمل کند. هیچ نتیجه‌ای نباید خرید جدید را پیش‌فرض بگیرد.

**مسیر اصلی:** Hero → Studio Upload؛ بخش توضیح ۳ مرحله‌ای (عکس فضا، بررسی تغییرها، تصمیم خرید) → نمونه تصویری → مجله → CTA استودیو.

**مسیر ثانویه:** `/blog/` با متن «راهنماهای انتخاب و تغییر دکوراسیون». این بخش به خوشه‌های مسئله‌محور مجله وصل می‌شود، نه صفحات ناموجود یا محصول خصوصی.

**عنوان پیشنهادی:** `طراحی دکوراسیون خانه با هوش مصنوعی از روی عکس | هما`.

**متای پیشنهادی:** `عکس خانه‌ات را در هما بررسی کن؛ ببین چه وسایلی را حفظ یا جابه‌جا کنی، چه چیزی نیاز به تغییر دارد و اگر خرید لازم بود، چه محصولی مناسب‌تر است.`

**Schema:** Organization و WebSite مبتنی بر داده واقعی public با لوگوی موجود. FAQPage و AggregateRating ساختگی، Product data خصوصی و claimهای موفقیت آزمایش‌نشده اضافه نشده‌اند.

## باقی‌مانده واقعی و مهم‌تر از تغییرات صرفاً محتوا

1. **P0: HTML اولیه قابل‌خزش در Production.** خروجی `index.html` static هنوز `<div id="root"></div>` است؛ متا و JSON-LD داخل head افزوده شده‌اند، اما متن اصلی در پاسخ HTML اولیه نیست. Googlebot قادر به اجرای JS است اما رندر ممکن است به تعویق بیفتد؛ دیگر خزنده‌ها ممکن است JS اجرا نکنند. راه‌حل مطلوب باید **معادل محتوایی برای انسان و خزنده** باشد: static prerender/SSR production-backed با تست همان artifact، نه محتوای مخفی فقط برای bot. مسیر runtime تولید مستقر و بلوک‌های `nginx` باید قبل از تغییر بررسی شوند. از `server.mjs` بدون build SSR قابل‌اجرا در Docker استفاده نکنید.
2. **P0: تست Live.** از محیط شبکه‌ای که دامنه را باز می‌کند 200/HTML اولیه برای انسان، Googlebot، OAI-SearchBot، Bingbot؛ canonical، index، لینک `/blog/`، JSON-LD، structured data و robots را بررسی کنید. تست با UA شبیه‌سازی‌شده IP اصیل خزنده را اثبات نمی‌کند.
3. **P0: Core Web Vitals.** LCP، INP، CLS صفحه واقعی را در موبایل و دسکتاپ با CrUX/PageSpeed / Search Console اندازه بگیرید. بهینه‌سازی JSX بدون این داده اثبات بهبود CWV نیست. سطوح منطقی بررسی: تصویر Hero، اندازه CSS/JS و پاسخ API محصولات.
4. **P1: آنالیتیکس قیف.** UTM/referrer ورودی صفحه اصلی و بلاگ؛ CTA → upload_completed → design_started → paid_conversion را با حفظ حریم خصوصی اندازه بگیرید. اندازه‌گیری درآمد/تبدیل هر مقاله را با داده معتبر انجام دهید.
5. **P1: اتصال جزئی‌تر به محتوا.** پس از تأیید وجود URLهای مقاله روی دامنه، دو یا سه لینک مقاله مسئله‌محورِ منتخب را در صفحه اصلی نمایش دهید؛ لینک‌های غیرموجود منتشر نکنید.
6. **P1: QA بصری.** خط‌بندی H1 فارسی و کنتراست CTA، دکمه‌های قبل/بعد در حالت لمس، keyboard, keyboard-focus, reduced-motion، 390px و 1440px را در مرورگر واقعی بررسی کنید.
7. **P2: ارتباط با کاربران و اعتماد.** فرایند انجام کار، محدودیت تصویرسازی و قوانین استفاده را به‌شکل شفاف نشان دهید؛ از آمار مشتری، رضایت و گواهی‌های بدون شاهد پرهیز کنید.

## تست و انتشار

`node --test scripts/homepage-quality.test.mjs`

`.github/workflows/homepage-quality.yml` همچنین `npm run build` را اجرا می‌کند. این QA تنها مختص شاخه PR است؛ به‌معنی استقرار Production نیست.

Workflow قدیمی `Frontend SEO gates` ممکن است به‌دلیل `dist/server/entry-server.mjs` شکست بخورد؛ نباید این خطا را با ساخت یک موفقیت صوری پنهان کرد. مسئول فنی ابتدا باید CI را با همان artifact واقعی Nginx + sidecar هماهنگ کند.

**عدم تغییر:** موتور طراحی، APIها، داده/قیمت کاتالوگ خصوصی، مسیر Sync بلاگ، قانون ربات سایت زنده و تنظیم ۴۸ ساعته worker.
