# صفحهٔ اصلی هما در مسیر Production

## معماری و خط مبنا

- مرجع سورس `codex/production-server-20261110` در `8752247` است. PR شمارهٔ ۱۸ روی `dev` است و هر دو شاخه بعد از `a696734` تغییرات جداگانه دارند. Hero، متن تصمیم‌گیری و مسیرهای ورودی PR شمارهٔ ۱۸ روی مرجع انتشار منتقل شدند تا مسیریابی عمومی، مجله و استودیوی فعلی در مبنای PR حضور داشته باشند.
- تصویر در حال اجرای بررسی‌شده `homa_openai_frontend:category-sections-20261107` بود. Nginx درخواست صفحهٔ اصلی و دیگر صفحات عمومی را به `render-bot.mjs` روی پورت داخلی 8081 می‌فرستد. Render Bot در زمان راه‌اندازی فایل‌های `marketing/*.html` را می‌خواند. `scripts/build-marketing.mjs` بعد از Vite این فایل‌ها را از کامپوننت‌های React تولید می‌کند. در مرورگر، Vite رفتار تعاملی SPA را راه‌اندازی می‌کند.
- مجله از Render Bot به API عمومی مجله می‌رسد. Nginx دارایی‌ها، robots و sitemap اصلی را از دیسک می‌دهد. صفحات استودیو از shell برنامه با هدر `noindex, follow` و مسیرهای حذف‌شدهٔ فروشگاه با 404 پاسخ می‌گیرند.
- در زمان بررسی، درخواست زندهٔ `/` با چهار User-Agent پاسخ 200 و HTML اولیهٔ ۳۳٬۸۰۶ بایتی شامل Hero و یک H1 داشت. لینک مجله در HTML بود و CTA اصلی لینک HTML به `/studio/upload` نداشت. `/blog/` پس از redirect و مسیر عمومی `/blog/cozy-bedroom-without-new-bed` پاسخ 200 دادند.
- `server.mjs` و artifact فرضی `dist/server/entry-server.mjs` بخشی از راه‌اندازی تصویر بررسی‌شده نیستند. تست مخصوص SSR قدیمی در `scripts/seo-legacy-ssr-check.mjs` قابل اجراست. گیت اصلی اکنون Docker و مسیر HTTP فعال را اجرا می‌کند.

## تغییرات و قیف

- هر شش بخش صفحهٔ اصلی در React تعاملی و prerender مشترک‌اند: معرفی، نمایش طراحی و خرید، مراحل خدمت، حفظ وسایل، راهنماهای تصویری و پرسش‌های متداول. HTML اولیه شامل یک H1، متن معرفی، لینک استودیو و مجله، title، description، canonical و Schemaهای Organization و WebSite است. بارگیری سراسری کاتالوگ و showcase مستقل از خانه حذف شد؛ ورودی محصول دارای شناسه حفظ شده است.
- راهبری بخش‌های اصلی و لینک جداگانهٔ «برای میزبان‌ها» در خانه و نسخهٔ HTML اولیه حضور دارد. مسیر `/hosts` جداگانه با HTTP 200 در گیت تأیید می‌شود.
- اسلایدر از کنترل native با نام دسترس‌پذیر استفاده می‌کند. هر breakpoint فقط تصویر WebP متناظر را preload می‌کند. ارتفاع تصویر در عرض موبایل تنظیم شده تا دکمه در ۳۹۰×۸۴۴ کامل دیده شود.
- هدر CSP زنده فقط فونت هم‌دامنه و `data:` را مجاز می‌کند. فونت‌های تعریف‌شدهٔ Vazirmatn، Noto Sans Arabic و Inter حالا با مجوزهای OFL از همین دامنه سرو می‌شوند. `font-display: swap` حفظ شده و پیش‌بارگذاری زودهنگام تصویر و Vazirmatn فقط روی سند صفحهٔ اصلی است. فونت نسبت به تصویر اولویت پایین‌تری دارد. فایل‌های Inter و Noto Sans Arabic از زیرمجموعه‌های Google Fonts برای زبان‌های فعال آمده‌اند.
- Umami رویدادهای `organic_landing`، `studio_cta_click`، `studio_upload_confirmed` و `studio_processing_started` را می‌گیرد. ارجاع از میزبان‌های موتورهای جست‌وجوی شناخته‌شده با حذف نشانگرهای تبلیغات شناخته می‌شود. آپلود قدیمی پس از ثبت موفق نشست شمارش می‌شود. در جریان گفت‌وگو اولین پیام مرحلهٔ سرور برای درخواست دارای عکس نشانگر دریافت عکس و شروع پردازش است. جلوگیری از تکرار دو رویداد آخر در همان تب و به ازای نشست انجام می‌شود. payload جدید شامل دستهٔ منبع است. کوئری، شناسهٔ خصوصی مسیر و عنوان گفت‌وگو حذف می‌شود. ارسال مشخصات حساب از مسیر شناسایی Umami و چند فیلد خصوصی از رویدادهای قدیمی نیز حذف شدند.
- CTA اصلی با آدرس `/studio` وارد جریان فعلی انتخاب اتاق و طراحی می‌شود. لینک اتاق خواب `/studio?room=bedroom` و مسیر قدیمی `/studio/upload` همچنان معتبرند.

## بازطراحی تجربه و محتوا — ۱۵ نوامبر

الهام از [Madespace](https://www.madespace.ai/) در مقیاس عکس‌ها، تیترهای کوتاه و روایت مراحل خدمت به کار رفته است. تصاویر، متن، نشان، فونت یا کد آن سایت وارد هما نشده‌اند. رنگ‌ها و فونت‌های فعلی هما حفظ شده‌اند. محور صفحه «از طراحی خونه‌ت، تا خرید وسایلش» است و نمایش طراحی و خرید بلافاصله پس از Hero قرار دارد.

نمونهٔ تعاملی سه حالت طراحی، انتخاب وسایل و ادامهٔ خرید دارد. نشانه‌های تصویر و گزینه‌های متنی انتخاب را تغییر می‌دهند و وضعیت انتخاب هنگام برگشت بین مراحل حفظ می‌شود. این بخش نمایش آموزشی است؛ قیمت، محصول موجود یا افزودن به سبد واقعی را جعل نمی‌کند. ادامهٔ واقعی با لینک استودیو انجام می‌شود و متن خرید مسیر فروشنده را توضیح می‌دهد.

عکس‌های موجود هما در `src/pages/ProductLanding/components/homepageMedia.ts` متمرکزند تا تصاویر اختصاصی بعدی جایگزین شوند. تصاویر فعلی به‌عنوان نمونهٔ تصویرسازی معرفی شده‌اند. راهنماهای تصویری به مقالات منتشرشده متصل‌اند؛ تصویر نمونه به‌عنوان پروژهٔ اجراشده یا محصول دقیق معرفی نشده است. متن‌ها برای فارسی، انگلیسی، عربی و ترکی در ترجمه‌ها قرار دارند.
## آزمون و انتشار

```sh
npm ci
npm run lint
npm test
npm run build
docker build -f deploy/openai/Dockerfile -t homa-home-seo:qa .
node scripts/seo-http-check.mjs homa-home-seo:qa
```

گیت Nginx و Render Bot برای چهار User-Agent برابری بایت‌به‌بایت HTML را بررسی می‌کند. robots، sitemap، noindex استودیو، 404 مسیر حذف‌شده و رفتار مجله در حالت مقالهٔ معتبر، مقالهٔ ناموجود و خطای upstream نیز بررسی می‌شوند. دادهٔ مجله در این تست fixture است. شبیه‌سازی User-Agent دربارهٔ دسترسی واقعی خزنده یا ایندکس‌شدن نتیجه‌ای نمی‌دهد.

گیت HTTP پس از بازطراحی پاس شد؛ چهار User-Agent پاسخ 200 با HTML یکسان ۳۰٬۱۱۲ بایتی دریافت کردند. فونت هم‌دامنه با MIME صحیح سرو شد و لینک اصلی `/studio` در HTML وجود داشت. ۳ تست Node و ۳۴۳ تست Vitest پاس شدند؛ lint و build نیز موفق بودند. بیلد هشدارهای قدیمی مربوط به Browserslist، کلیدهای تکراری در JSON زبان‌ها و اندازهٔ chunk را گزارش می‌کند.

### آزمون مرورگر

Chrome در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ پیکسل آزمایش شد. چهار زبان جهت درست و متن ترجمه‌شده داشتند و بیرون‌زدگی افقی دیده نشد. تصاویر بعد از پیمایش کامل بارگیری شدند. اسلایدر با صفحه‌کلید، لمس و موس، انتخاب نشانه‌های تصویر با Enter، حفظ انتخاب بین مراحل و FAQ بومی بررسی شدند. CTA اصلی در نخستین نما قابل مشاهده بود.

نسخهٔ لوکال از image بازطراحی‌شده روی `http://127.0.0.1:18081/` سرو می‌شود. آزمون مرورگر API را به پاسخ fixture 503 و مبدأهای بیرونی را به مسدودسازی هدایت می‌کند. این بررسی تأیید اجرای مدل، ارسال OTP یا خرید واقعی نیست. HTML اولیه و FAQ بدون JavaScript نیز با موفقیت بررسی شدند. اعداد آزمایشگاهی نسخهٔ قبلی برای این بازطراحی معتبر نیستند.

### عملکرد آزمایشگاهی این بازطراحی

روی همان ماشین، Chrome با تأخیر شبکهٔ ۴۰ میلی‌ثانیه و دریافت ۱۰ مگابیت‌برثانیه، هر نسخه سه بار در context تازه اجرا شد. موبایل ۳۹۰×۸۴۴ با CPU چهار برابر کندتر و دسکتاپ ۱۴۴۰×۹۰۰ بود. خط مبنا همان artifact ثبت‌شدهٔ Production است؛ APIها fixture و مبدأهای بیرونی مسدود بودند.

| معیار | خط مبنا | بازطراحی |
| --- | ---: | ---: |
| میانهٔ LCP موبایل | ۱٫۰۸ ثانیه | ۱٫۸۴ ثانیه |
| میانهٔ LCP دسکتاپ | ۰٫۶۶ ثانیه | ۰٫۸۲ ثانیه |
| بیشترین CLS موبایل | ۰ | ۰ |
| بیشترین CLS دسکتاپ | ۰ | ۰٫۰۰۱۳ |
| JavaScript بارگذاری اولیه | ۲۹۲٫۴ KiB | ۳۰۲٫۳ KiB |

LCP موبایل بازطراحی در سه نمونه از ۱٫۴۷ تا ۳٫۶۸ ثانیه متغیر بود. این دادهٔ کم‌نمونه ادعای بهبود سرعت را پشتیبانی نمی‌کند؛ افزایش محتوای تعاملی حدود ۹٫۹ KiB به JavaScript اولیه افزوده است. LCP تصویر Hero بود. p75 و INP کاربران واقعی اندازه‌گیری نشده‌اند و پس از انتشار باید جداگانه بررسی شوند.
### Deployment پس از تأیید

1. image ID و tag کانتینر فعلی، تنظیمات فعال Dokploy و نسخهٔ Compose را ثبت و نسخهٔ بازگشت را در سرور حفظ کن. نسخهٔ Compose فعال و تنظیمات محیطی را با تصویر تأییدشده تطبیق بده.
2. از SHA نهایی روی CI یا ماشین محلی بیلد کن. مقادیر build-time موجود را از شناسنامهٔ انتشار تأیید کن. تصویر را با SHA یکتا برچسب بزن و گیت HTTP را روی همان image اجرا کن.
3. تصویر تأییدشده را با SHA256 آرشیو یا digest منتقل و image ID را بعد از بارگیری تطبیق بده. در استقرار بدون بیلد فقط تصویر سرویس frontend را جایگزین کن. تنظیمات runtime از جمله OTP، API، origin رسانه، مجله و Umami را از تنظیمات فعال حفظ کن.
4. با یک نشست تازه، HTML زندهٔ خانه، CTA تا فرم عکس، تصاویر، robots، sitemap و یک مقالهٔ منتشرشده را smoke test کن. در Umami دریافت مراحل قیف را با دادهٔ آزمون مجاز بررسی کن. سلامت و نرخ خطای HTML را بعد از تعویض تصویر کنترل کن.

### Rollback

در صورت خطای سلامت، 5xx خانه یا مجله، شکست بارگیری asset یا باز نشدن فرم استودیو، tag و Compose ذخیره‌شده را برای همان سرویس frontend بازگردان. پس از سلامت کانتینر، `/`، `/studio/upload` و `/blog` را دوباره از بیرون بررسی کن.

## موارد باقی‌مانده

1. **اولویت بالا**. تأیید جریان احرازشده و یک اجرای طراحی در Staging متصل به backend آزمایشی. برای درخواست واقعی، حساب تست و ورودی مجاز لازم است.
2. **اولویت بالا**. ثبت خرید فقط از رویداد پرداخت تأییدشده یا گزارش فروش قابل تطبیق. کلیک خرید و ثبت درخواست اعتبار در این شاخه اثبات پرداخت محسوب نمی‌شوند.
3. **اولویت متوسط**. بررسی p75 میدانی برای LCP، CLS و INP پس از انتشار و جمع‌شدن نمونه. درخواست PageSpeed API در این بررسی با HTTP 429 پاسخ داد.
